# Самокат Рядом — учебное демо проката электросамокатов

Тема: прокат электросамокатов в Московском районе Санкт-Петербурга.
Сайт сделан на чистом HTML, CSS и JavaScript (ES-модуль), без фреймворков, сборщика и сервера.

> Учебное демо: резервы сохраняются только в этом браузере. Реального запуска самоката и оплаты нет.

## Запуск

Нужен любой статический HTTP-сервер (ES-модули не загружаются из `file://`). Например, Python:

```bash
python -m http.server 8000
```

Команду запускают в папке сайта, затем открывают <http://localhost:8000>.

## Возможности

- **Схема района** — своя HTML/CSS-схема с SVG-фоном: Московский проспект, улицы, сквер, парк, остановка. Самокаты — кнопки поверх схемы (`left/top` в процентах, `translate(-50%, -50%)`).
- **Статусы**: «Свободен», «Выбран», «Занят», «Низкий заряд». Отличаются цветом, обводкой (у занятых — пунктир), значком (✓, ×, !) и текстом в `aria-label` и `title`. Легенда под схемой.
- **Список** тех же самокатов: название, модель, «заряд 75%», цена («60 ₽ + 6 ₽/мин»), статус, кнопка «Выбрать».
- **Фильтры** «Минимальный заряд» (любой / ≥30% / ≥50% / ≥80%) и «Тариф» (Все / Стандарт) действуют на схему и список одновременно. Если выбранный самокат выпал из фильтра, выбор снимается с сообщением. Пустой результат: «Ничего не найдено. Измените фильтры.» Сброс фильтров не трогает резервы.
- **Карточка и форма резерва** в стиле мобильного приложения проката: заряд и примерный запас хода, выбор тарифа карточками (поминутный или пакет минут), переключатель подписки «Плюс», расчёт «К оплате при старте» и кнопка «Подтвердить резерв». Время поездки заранее не выбирается: аренду человек завершает сам.
- **Мои резервы**: запись появляется сразу после подтверждения, самокат становится занятым на схеме и в списке. Отмена по одному и «Очистить мои резервы» с подтверждением.
- **localStorage**: сохранение, восстановление при загрузке, обработка повреждённых данных, синхронизация между вкладками.

## Правила по заряду и сортировка

| Заряд | Поведение |
|---|---|
| < 10% | «На обслуживании»: не показывается на схеме и в списке, резерв невозможен |
| 10–19% | Доступен, но с предупреждением «Низкий заряд — хватит ненадолго»; всегда в конце списка |
| ≥ 20% | Обычный |

Порядок списка: свободные по убыванию заряда → занятые → самокаты с зарядом ниже 20% (среди них сначала свободные).
Два самоката (№7 и №8) изначально заняты «другим пользователем»: их нельзя выбрать, зарезервировать и отменить.

## Тарифы и расчёт

| Вариант | Цена | Срок |
|---|---|---|
| Поминутный (тариф «Стандарт») | старт 60 ₽ + 6 ₽/мин | без лимита |
| Пакет 15 минут | 80 ₽ (≈5,33 ₽/мин), старт входит | 1 день |
| Пакет 30 минут | 150 ₽ (5 ₽/мин), старт входит | 1 день |
| Пакет 60 минут | 270 ₽ (4,50 ₽/мин), старт входит | 7 дней |
| Подписка «Плюс» | 0 ₽ в демо; старт бесплатно и −15% к поездке и пакетам | — |

Минуты сверх пакета стоят 6 ₽ (с «Плюс» — 5,10 ₽). В карточках пакетов зачёркнута цена тех же минут на поминутном тарифе (например, 15 минут: 60 + 15 × 6 = 150 ₽).

В коде две чистые функции:

- `getOffer(packageKey, hasSubscription)` — что платится при старте (`payNow`) и сколько стоит каждая следующая минута (`minuteRate`). По ней строятся карточки тарифов, разбивка и запись резерва.
- `calculatePrice(minutes, packageKey, hasSubscription)` — стоимость уже завершённой поездки:
  1. Пакет и минут не больше пакета → цена пакета.
  2. Минут больше пакета → цена пакета + (минуты − минуты пакета) × 6.
  3. Без пакета → старт 60 ₽ + минуты × 6.
  4. С «Плюс» → старт 0 ₽, `Math.round(стоимость поездки × 0.85)` (считается в целых числах, без ошибок округления float).

К оплате при старте (`getOffer`):

| Тариф | Без «Плюс» | С «Плюс» |
|---|---|---|
| Поминутный | 60 ₽, дальше 6 ₽/мин | 0 ₽, дальше 5,10 ₽/мин |
| 15 минут | 80 ₽ | 68 ₽ |
| 30 минут | 150 ₽ | 128 ₽ |
| 60 минут | 270 ₽ | 230 ₽ |

Стоимость завершённой поездки (`calculatePrice`):

| Минуты | Тариф | «Плюс» | Итог |
|---|---|---|---|
| 20 | поминутный | нет | 60 + 120 = 180 ₽ |
| 20 | поминутный | да | 0 + round(102) = 102 ₽ |
| 10 | 15 минут | нет | 80 ₽ |
| 40 | 30 минут | нет | 150 + 10 × 6 = 210 ₽ |
| 40 | 30 минут | да | round(178,5) = 179 ₽ |
| 120 | 60 минут | нет | 270 + 60 × 6 = 630 ₽ |

Проверка в консоли DevTools (модуль уже загружен, повторно он не выполняется):

```js
const { getOffer, calculatePrice } = await import("./app.js");
getOffer("none", false).payNow;          // 60
getOffer("p30", true).payNow;            // 128
calculatePrice(40, "p30", true).total;   // 179
```

## Архитектура

- `SCOOTERS` — единственный массив данных самокатов; из него строятся схема, список и карточка. Тарифы, пакеты и подписка — объекты `TARIFFS`, `PACKAGES`, `SUBSCRIPTION`; из них же собираются карточки выбора тарифа и блок «Тарифы».
- Единое состояние: `state = { selectedId, filters: { minBattery, tariff }, ownBookings }`.
- Занятость не хранится отдельно, а вычисляется: `ownBookings ∪ initiallyBusy`. Схема и список берут её из одной функции `getOccupancy()`, поэтому рассинхрона нет.
- Любое действие меняет `state` и вызывает `render()`, которая перерисовывает схему, список, карточку и «Мои резервы» (`renderMap`, `renderList`, `renderCard`, `renderBookings`).
- Выбор в форме (`ui.form`: тариф и «Плюс») хранится отдельно от состояния; расчёт обновляется сразу при изменении.
- Двойное подтверждение не создаёт дубликат: после первого резерва самокат занят, выбор снят, форма скрыта и сброшена, а обработчик дополнительно проверяет, что самокат ещё свободен.
- Данные из localStorage выводятся через экранирование HTML, поэтому подменённые записи не могут внедрить разметку.

## Хранение

Ключ localStorage: **`scooter_bookings_v1`**. Значение — JSON-массив записей:

```json
{
  "id": "b-mgx3k2a1-4f9q",
  "scooterId": "s1",
  "scooterName": "Самокат №1",
  "model": "Ninebot Max G30",
  "packageKey": "p30",
  "hasSubscription": true,
  "total": 128,
  "createdAt": "2026-10-22T10:15:00.000Z"
}
```

`packageKey`: `"none"` (поминутный), `"p15"`, `"p30"` или `"p60"`. `total` — сумма к оплате при старте.

Если JSON повреждён или структура неверная (не массив, пропущенные или неверные поля, неизвестный самокат, изначально занятый самокат, дубликаты), показывается сообщение «Не удалось прочитать сохранённые резервы, данные сброшены», ключ удаляется и работа продолжается с пустым списком. Проверка в консоли:

```js
localStorage.setItem("scooter_bookings_v1", "{битый json"); location.reload();
localStorage.setItem("scooter_bookings_v1", '{"a": 1}'); location.reload();
localStorage.setItem("scooter_bookings_v1", '[{"id": 1}]'); location.reload();
```

## Доступность и адаптив

- Семантика: `header`, `nav`, `main`, `section`, `form`, `fieldset`, `button`; все поля связаны с `label`.
- Схема и список работают с клавиатуры: Tab до кнопки, Enter или Space — выбор. У всех интерактивных элементов виден фокус (`:focus-visible`), есть ссылка «Перейти к основному содержимому».
- Тарифы — настоящая группа радиокнопок (`fieldset` + `legend`, стрелки переключают вариант), «Плюс» — чекбокс с `role="switch"`. Итог — элемент `<output>`, короткие сообщения — через live-регион `aria-live="polite"`.
- Фокус после действий: выбор самоката → заголовок карточки; резерв → сообщение «Резерв оформлен»; отмена → следующая кнопка «Отменить» или заголовок «Мои резервы».
- Статусы подписаны текстом, а не только цветом; контраст текста не ниже 4.5:1.
- Проверено на ширине 360, 768 и 1280 px. Кнопки на схеме не перекрываются на 360 px; на широкой схеме подпись полная («Самокат №1»), на узкой короткая («№1»). При увеличении 200% страница перестраивается в одну колонку без горизонтальной прокрутки.

## Ограничения учебного демо

- Нет оплаты, авторизации и реального запуска самоката; поездка не идёт и не завершается.
- Резервы хранятся только в localStorage этого браузера и не уходят на сервер; другие устройства их не видят.
- Самокаты, их модели, заряд, запас хода и места на схеме вымышлены. Сайт не связан с реальными сервисами проката.

## Изображения и ресурсы

Внешних картинок, шрифтов, CDN и API нет. Иконки — эмодзи и символы (🛴, 🎓, ⚠, ✅, ✦) и inline SVG (логотип, схема района), шрифт — системный. Сайт работает без интернета.

## Яндекс Карты

Интеграция Яндекс Карт (JavaScript API с ключом и ограничением по HTTP Referer) — дополнительная опция и в основную версию не входит. Основная версия — собственная схема района и только локальные ресурсы, поэтому ей не нужны ключи и сеть.

Сайт сгенерирован нейросетью Claude (Anthropic) по подробному техническому заданию, затем проверен в браузере: консоль без ошибок, сценарии резерва, отмены и повреждённого localStorage, ширина 360/768/1280 px.

Полезные промпты:

1. **Основное ТЗ.** «Ты — senior frontend-разработчик. Создай учебный сайт „прокат самокатов“ на чистом HTML/CSS/JS с ES-модулями, без сборщика и сервера: 8 самокатов в одном массиве, схема района с кнопками, фильтры, тарифы и пакеты, подписка, расчёт отдельной функцией, резервы в localStorage, доступность и адаптив…»
   Результат: четыре связных файла с единым состоянием и функцией `render()`.
2. **Доработка по примеру приложения.** «В стандартном тарифе старт поездки должен стоить 60 ₽; убери выбор количества минут при бронировании (человек сам решит, когда закончить аренду), пакеты минут оставь. Пример оформления — скриншоты мобильного приложения аренды самокатов.»
   Результат: выбор тарифа карточками с зачёркнутой обычной ценой и ценой минуты, переключатель подписки, сумма «к оплате при старте».
3. **Координаты на схеме.** «Подбери координаты x/y в процентах для 8 кнопок на схеме 16:10, чтобы на экране 360 px они не перекрывались и не выходили за края, а подписи района оставались видны.»
   Результат: координаты в диапазоне 15–85% по горизонтали и 20–82% по вертикали; пары с близкой высотой разнесены минимум на 27% по ширине.
